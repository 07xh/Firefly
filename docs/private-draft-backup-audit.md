# 私人草稿与 R2 历史备份一致性检查（开发版）

本功能属于后台只读诊断，**不会保存、覆盖、删除或自动修复任何私人草稿和备份**。只影响管理员页面 `/admin/system/` 和受登录保护的 `GET /api/admin/private-draft-audit/?slug=...`，不改博客访客前台 UI。

## 如何使用

进入管理员后台 → 系统运行状态 → “核对私人草稿与 R2 备份”，填写一篇私人草稿的文件名（不含 `.md`、`.mdx` 后缀），手动点击核对。

返回三种结果：

- `verified`：这次**可覆盖的版本范围内**，当前稿与已发现历史版本在 R2 中存在可读、内容相同的备份。**不代表所有时间点或整个 Cloudflare 账号的灾难恢复可靠性。**
- `attention`：发现 R2 缺失、损坏、同版本内容不一致或 KV/D1 历史版本损坏。仅显示问题类型与版本 UUID，不泄露 Markdown 原文、密码或备份对象数据。
- `incomplete`：检测版本数量超出上限、存在未核对的分页，或核对期间当前稿发生变化。**不能把它当作检查通过。**

此外会单独显示“仅在 R2 存在的恢复版本”数量。这类孤立版本可能是 KV/D1 更新失败后留下的正常恢复副本，不会自动删除。

## 安全边界

1. 为避免 Worker 单请求过多存储操作，本版**每篇最多完整比对 12 个不同版本**（包括当前版本、KV/D1 历史和 R2-only 副本）；超过上限显式返回 `incomplete`。历史更多时需分批核验能力，不得静默漏检。
2. 读取**当前启用的** KV 或 D1 主存储，以及专用非公开 R2 Bucket；缺任意必要绑定时返回 503，不会当作没有备份。
3. 核对文件格式、版本号、修改时间、正文与扩展名是否一致；不返回原文。核对前后对当前稿再读取一次，发现变化则返回不完整。
4. KV 的最终一致性、D1/R2 之间没有共享事务，故一次成功结果不保证并发写入期间的完整性。
5. 旧 KV 历史与 R2 对账在 D1 切换后仍需要**独立迁移验收**。此接口只核对当前选定的存储后端，不能替代人工验证旧 KV 已全部迁移。
6. 这不是异地备份服务。使用同一 Cloudflare 账号的 KV 与 R2 不能替代跨账号/跨云备份。
7. 接口位于 `/api/admin/`，继承管理员会话认证；`Cache-Control: private, no-store`。若授权失败不能返回任何草稿信息。

## 上线前检查

- [ ] 登录/登出、CSRF/Origin（只读 GET）保护校验
- [ ] 在预览 Worker 中用合成草稿实际写入 R2 后读取、损坏、缺失、冲突与恢复演练
- [ ] D1 模式与 KV 模式下均验证已知内容
- [ ] 超过 12 个历史版本时如实显示“不完整”
- [ ] 无任何私人正文、密钥或敏感报错进入响应/日志
- [ ] 前台视觉、文章原文和布局零变化

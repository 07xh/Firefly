# 图床删除保护（开发中的后端防护）

本分支基于原图床 PR #42，不修改博客访客可见的前台 UI。

## 新增保护
- 用户在后台点击删除图片时，服务端在真正调用图床删除 API 前，从 GitHub 文章源文件检查实际引用。
- 如果私人草稿 KV 已经绑定，会同时检查活跃草稿、已删除草稿的 KV 历史版本以及 R2 私人备份记录。
- 任何来源包含目标图片路径时，返回 HTTP 409，并提示该图片的引用位置；不能直接删除。
- GitHub 令牌缺失、文章目录截断、读取失败、私有草稿历史无法核验、分页超出限制或已切换但尚未接入 D1 引用检查时，返回 503，**拒绝删除**。
- 限制 GitHub 检查文章总数不超过 200；草稿历史与 R2 备份单类别最多各 500 条。超过上限时停止删除，避免假称已完整核验。
- 保留原有图片格式与体积限制、图床 Bearer Token 仅存 Worker Secret、服务端代理上传及管理。

## 重要局限
- 当前用 Markdown/MDX 原文中的 HTTP 图片路径查找引用。动态拼接的 URL、通过变量导入的路径或运行时生成的链接，可能无法识别。不能把检查结果当作绝对无引用的证明。
- 对历史备份中旧图片的引用也会拦截删除。请优先维护备份、引用迁移与图片回收站，而不是强制删除。
- 由于原图床 PR #42 尚未真实与图床 API 联调，本分支仍为 Draft，不能直接部署生产。
- 当私人草稿后端切换至 D1，需要按阶段路线图把 D1 文章引用也纳入检索后再启用删除。当前如果判断 D1 模式，将 fail closed。
- 图片一旦由公开图床托管，保存私人草稿不会把这张图片自动变成私密资源。


## D1 私人草稿模式兼容（后续补强）

- 当 `FIREFLY_PRIVATE_DRAFT_BACKEND=d1` 时，删除前会使用只读 SQL 检查 D1 `private_drafts` 和 `private_draft_revisions` 的全部正文引用。
- 若迁移后旧 KV 仍然绑定，会继续扫描旧 KV 当前稿与旧历史快照，避免遗漏旧备份；同时要求独立 R2 历史可以读取。
- D1 不可访问、缺少绑定、版本记录异常、超过扫描上限时一律禁止删除。当前检查使用分页只读查询，不会修改 D1。
- 真实 D1 连接、可能的并发新引用以及动态拼接的图片路径，仍需要浏览器/运行时联调。该功能不是无误删保证。

## 预览验收
1. 无 GitHub Contents Token → 503，图片不删除。
2. 被 GitHub 公开文章引用 → 409，提示引用位置。
3. 被私人草稿（包含历史版本）引用 → 409，不删除。
4. R2 与 KV 历史读取失败 → 503，不删除。
5. 未被引用的测试图片 → 调用图床删除 API；确认返回成功后刷新后台图库。
6. 已引用的旧图、图片带中文/空格/百分号编码、多个文章引用路径分别回归验证。
7. 验证所有前台页面/主题/布局不变。

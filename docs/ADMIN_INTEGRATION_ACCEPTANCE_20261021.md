# Firefly 后台集成验收清单（2026-10-21）

本分支从 [PR #63](https://github.com/07xh/Firefly/pull/63) 的开发提交派生，用于整合验收。**不部署，不合并 master，不改已有文章内容或博客访客前台。**

## 已核对的代码依赖

- 私人草稿和编辑器功能为累积式分支，最新 [PR #63](https://github.com/07xh/Firefly/pull/63) 相对 master 有约 191 个提交、46 个改动文件，涵盖 #43–#54、#57–#62 的多批改动。
- [PR #42](https://github.com/07xh/Firefly/pull/42) 的 ImgBed 图床功能与 #63 **存在分支分叉**，并非已经包含在 #63 中。它的直接依赖处理见 #51 / #56；不应直接强行把前台/后台编辑器文件互相覆盖。
- [PR #55](https://github.com/07xh/Firefly/pull/55) 的 GitHub workflow 目标分支修复尚未正式合并；目前 CI 对 master 目标 PR 可以运行，对以其他开发分支为目标的 PR 不能直接假定完整执行。
- 前台冻结是文件级保护；并不等价于用户界面像素级截图对比，也不能证明所有 API 行为兼容。

## 本批可验证变更

1. 修复前台冻结检查对后台安全、性能、集成分支识别不全的问题；现在同时检查删除、复制和重命名的原/目标路径。
2. R2 私人历史备份不能只检查存在 Markdown 头部；必须仍然声明 `draft: true`，并具有非空更新时间，否则拒绝写入/读取为有效恢复数据。
3. R2 目录内同一版本重复列出视为异常对象，而不是当作完整备份；非法返回游标直接报错。
4. 执行 `node --test scripts/check-admin-only-changes.test.mjs` 和 CI 的私人草稿/R2 回归测试以及 Cloudflare 无部署构建。

## 之后的合并策略

1. 保留现有 master 与生产数据，先验证 [PR #43](https://github.com/07xh/Firefly/pull/43) 的会话保护及 #44–#50 的存储路径。
2. 基于合成数据在隔离的预览 Worker 完成 KV/D1/R2 真实读写与恢复；对草稿导出离线备份，不使用真实旧稿测试破坏性迁移。
3. 使用对比和人工审阅确认 #63 中含有哪些先前改动，再按依赖拆分/压缩；**禁止把 #43–#63 的叠加 PR 逐个合并造成重复写入。**
4. ImgBed 另行验收 #42/#51/#56；仅在两条测试线验证后整合冲突文件。
5. 只有自动化、浏览器 E2E、线上配置及回滚验收通过，且前台 UI 保持不变，才考虑合并或部署。 

文档中的“未测”必须实际完成才能更新，不能由 GitHub Actions build success 推定。

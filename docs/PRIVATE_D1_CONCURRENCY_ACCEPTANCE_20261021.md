# 第三批：私人草稿 D1 存储一致性与并发故障验收（2026-10-21）

> 状态：仅提交开发分支 + CI 回归。**没有实际 Cloudflare D1/KV/R2 绑定或生产草稿操作。**

## 已新增的可自动检查内容

1. D1 INSERT/UPDATE 和历史版本插入前，正文结构、schema、UUID、slug、文件类型、修改时间均与索引元数据匹配；需要 `draft: true`，禁止未知扩展名静默变成 Markdown。
2. 模拟同一草稿两个客户端同时读取同一旧版本，各自写入独立 R2 不可变备份，最后只有一个 D1 CAS UPDATE 成功；失败客户端收到 409，成功正文不能被旧版本覆盖。
3. 模拟 R2 已确认备份、但 D1 当前稿更新报错；旧正文和旧版本号原样保留，新的孤立 R2 备份不可当作已保存的当前稿。
4. 模拟篡改的 D1 当前/历史记录、无 `draft: true` 以及超过 500 KB 的内容被拒绝，并保持数据库行不变。
5. D1 读取现有当前稿和历史记录时也重新核对已存索引与正文，拒绝因索引损坏而默默把 MDX 解释成 Markdown；列表遇到格式不合法的索引字段时明确报错。

6. KV→D1 迁移收集历史版本时，跨分页重复版本必须报 503；仅仅检查游标前进不足以证明没有遗漏历史。KV 与 R2 仍可合法地拥有同一版本，但各自的多页列表不能重复交付该版本。
7. 使用模拟 D1/R2 完整执行删除后历史恢复，要求新版本号、旧版本备份保持不变，复杂 MDX、CRLF 换行、中文、公式和组件源码逐字相同。

## 后续隔离真实环境任务

- 创建单独命名的预览 Worker，使用**专用的测试** D1 数据库、KV 命名空间和不公开的 R2 Bucket，绝不引用生产绑定。
- 对预览 D1 执行 `migrations/0001_private_drafts_d1.sql`，只写入合成的非敏感 MDX。
- 按顺序检查：未登录 401 → 创建版本 → 编辑冲突 409 → 历史版本恢复 → R2 不可变性 → D1 短暂故障拒绝覆盖 → 删除后的恢复。
- 校验整个过程中无 Token、原文、数据库凭据进入 CI 公开日志；应用级 JSON 错误不能泄露正文。
- 保留生产 KV 的历史原文，不自动迁移或切换 `FIREFLY_PRIVATE_DRAFT_BACKEND`。

## 目前已知边界

- SQLite 单语句 CAS 不能覆盖真实 Cloudflare 服务故障和 KV 最终一致性，真实环境验证仍不可省略。
- R2 与 D1 没有跨服务原子事务，失败后允许保留孤立版本，但不能把它错误标记为当前保存成功。
- 当前单篇迁移历史上限为 40；备份审计最多核验 12 个版本。超过上限不得宣布全部迁移/全部备份已完整。
- 本分支基于 PR #64 的累计安全分支，**不能独立于其依赖直接合并 master**；需在隔离的集成分支按顺序验收。

## 六阶段计划与完成条件

### 阶段 1 — 私人草稿版本历史、回收站与恢复（P0）
- [ ] 历史快照：保存前验证版本，为现有/新建草稿生成不可变快照
- [ ] 历史管理 API：分页列举、查看版本原文、从历史恢复为新版本
- [ ] 删除之前保存恢复点；已删除草稿仅允许在不存在同名当前稿时恢复
- [ ] 后台“历史版本”入口，选择版本、确认恢复、刷新编辑器，避免未保存更改丢失
- [ ] 导出 Markdown/MDX 作为离线备份，不剥离 import/特殊语法
- [ ] 验证版本损坏、部分写入、旧版冲突、删除恢复、无法连接 KV、权限到期场景
- [ ] 审查 PR #44/#45 代码与兼容性，分阶段合并；不可越过真实 KV 联调直接上线

验收：单元测试、Astro Check、Node 22/23 与 Cloudflare build 通过；预览 Worker 中验证 401/503/CRUD/历史恢复，文章内容逐字检查。

### 阶段 2 — 独立备份、并发事务与数据保密（P0）
- [ ] 设计 Cloudflare KV + D1/DO/R2 组合，优先用支持原子 compare-and-swap 的存储作真实主数据
- [ ] 独立备份存储（不要只依赖同一 KV 的历史键），备份定期校验与真实恢复演练
- [ ] 防止多个设备并发覆盖与地区 KV 最终一致性导致的数据冲突
- [ ] 保证私人草稿和密码不进入公开 GitHub、构建日志、未经授权的 AI 服务和公开图床
- [ ] 旧公开草稿人工迁移、原文对比、保留本地备份；评估 Git 历史及 Fork 暴露风险
- [ ] 客户端错误时只阻止写入，不丢失当前编辑内容；制定回滚方案

验收：恢复测试及并发冲突演练；完整授权；任何“私人”文件都不会被默默转为公开文章。

### 阶段 3 — 无损可视化编辑器与自然语言操作（P1）
- [ ] 减少 import/HTML/MDX/Markdown 源码暴露；保留源码模式
- [ ] 公式、图片、表格、引用、Tabs、Steps、Badge、callout、details 等可视化预览/编辑
- [ ] 原文往返无损：复杂 MDX 特殊语法、代码示例、公式、图片路径均保持
- [ ] 粘贴、拖拽和图库插入图片直接预览，失败保留原文与恢复入口
- [ ] 大型文章性能、可撤销编辑、草稿自动本地恢复、Android 平板交互优化
- [ ] 拆分编辑模块，排除多个插件实例和重复事件监听

验收：真实文章样本回归，不用通用示意替代原文，也不得静默删除特殊组件。

### 阶段 4 — 个人图床 / 媒体中心（P1）
- [ ] 审查并验证 PR #42 Sanyue ImgBed 接入
- [ ] 图片上传、目录、搜索、链接复制、Markdown/MDX 原位插入、批量选择
- [ ] 删除前检查文章引用，二次确认，避免误删正在使用的图片
- [ ] 图片 token 只放 Worker Secrets，保护后台代理、上传大小、文件类型、权限和限流
- [ ] 私人稿图片与公开图床的权限隔离、独立备份与恢复

验收：在预览环境端到端测试上传、搜索、插入和删除，不凭 CI 通过宣称图床已上线。

### 阶段 5 — 后台管理中心重构（P1）
- [ ] 统一文章、草稿、分类标签、媒体、AI 兼容服务商、全局配置和系统状态
- [ ] 全部后台常用操作可使用中文自然语言、表单、直接预览完成
- [ ] 在不改变前台 UI 的前提下管理已有配置项，杜绝写入破坏性默认值
- [ ] 明确公开文章/私人草稿/定时文章/已删除历史的状态及操作权限
- [ ] 提供加载、保存、失败、冲突、部署中的真实状态反馈
- [ ] 桌面/平板/移动端后台导航、键盘无障碍与撤销能力

验收：后台实际交互回归；前台可视化快照一致。

### 阶段 6 — 代码优化、安全与正式上线验收（P1）
- [ ] 拆分大型 src/pages/admin/index.astro，移除重复 render/refresh/submit 猴子补丁
- [ ] 后台文章索引与分页缓存、减少每次加载全部正文的 GitHub API 调用
- [ ] 整理重叠 Cloudflare/GitHub Actions 工作流，明确唯一可信生产部署路径
- [ ] 安全检查：Cookie/CSRF/Origin/KV、权限、错误日志脱敏、Server Secrets
- [ ] 自动化 + 浏览器 E2E：登录、草稿、发布、导入、导出、恢复、图床、AI、设置
- [ ] 分支测试、保护 master、备份、预览部署、灰度上线、回滚及生产健康检查
- [ ] 检查所有前台页面视觉、路由、正文、主题与交互一致，不添加前台 UI 优化

验收：全部必需检查通过，真实用户路径验证，能够回滚，且前台 UI 完全不变。

## 运行原则与依赖关系

1. P0 先于 P1：草稿不丢失与私人数据不公开优先于界面美化。
2. 每次在独立分支实施；每个逻辑阶段有自己的 PR；不得直接推送 master。
3. 未绑定专用存储时，私人草稿写入直接报错，不允许回退公开 GitHub。
4. 明确区分单元测试/构建成功与真实 Cloudflare Worker + KV 联调成功。
5. **不把同一 KV 内的版本历史叫作独立灾难备份。**
6. 现有公开 GitHub 历史和密码不能靠新接口自动变得私密。
7. 管理员登录密码和图床/API 密钥一律保存在 Cloudflare Secrets，不放入聊天、前端或 GitHub。
8. 未经实际验收和允许，不合并高风险 PR 或改动真实生产数据。
9. 新增历史版本与备份操作时，始终先确认源数据安全，再考虑迁移或删除。
10. 任何 PR 与 master 对比都必须确认不存在前台组件、布局、样式、文章正文更改。

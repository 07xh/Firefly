# 后台文章列表响应优化（开发阶段）

**严格仅改后台**。公开博客页面、文章正文、路由、样式、布局不变。

## 行为

- 旧 `GET /api/admin/articles/` 仍按原格式返回全文，兼容未升级的其他后台客户端。
- 新 `GET /api/admin/articles/?summary=1` 返回列表摘要，**不把所有公开文章全文返回到浏览器**；仍从 GitHub 读取原文用于解析标题、标签、日期和草稿状态。该批降低网络响应负荷与平板端内存占用，**暂未减少 GitHub 上游读取次数**。
- 点击单篇公开文章时，编辑器通过 `GET /api/admin/articles/?path=<文章路径>` 读取完整 Markdown/MDX 原文。
- 服务端只接受 `src/content/posts/` 下的合法 `.md` / `.mdx` 路径，拒绝任意目录读取。
- 在将正文写入编辑器前核对 GitHub 文件 SHA；如果列表加载后文章被修改，则要求刷新而不是使用过期内容。
- 原有私人 KV/D1 草稿仍按独立接口读取，无需改动。
- 浏览器中所有管理 GET 均无请求正文，保证 Fetch 规范兼容。

## 风险与后续

- 如果文章数越来越大，上游 GitHub API 的每篇文章读取仍可能造成速率限制。下一阶段可增加有 SHA 的摘要缓存和受控并发，但不能缓存/公开私人稿或擅自修改前台。
- 版本检查只减少意外覆盖，实际提交仍依赖已有 GitHub SHA 乐观并发检查。
- 本功能仍需在预览环境测试编辑、保存、搜索、复杂 MDX 语法往返与安卓平板流畅性。
- 不能用自动化构建成功代替浏览器端到端联调。

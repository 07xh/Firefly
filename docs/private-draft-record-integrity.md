# 私人草稿存储记录完整性保护（开发分支）

这项保护仅对管理员私人草稿的 KV/D1 读取、更新、删除、历史读取和恢复生效，**不修改博客前台 UI、公开文章或生产数据**。

## 拒绝静默纠正损坏的记录

- 当前稿和历史记录必须包含符合当前格式的 schema、slug、UUID 版本、`md`/`mdx` 扩展名、非空更新时间和有效私人草稿 Markdown/MDX 正文。
- 正文必须仍然有包含 `draft: true` 的 frontmatter，且不得超过 500 KB；不能把本应是私密草稿的损坏数据默认为公开文章。
- 原来异常的扩展名可能被默认为 `.md`；现在会返回错误，而不把未知类型当作 Markdown。
- 如果读取中发现损坏，服务器拒绝随后覆盖、删除或从损坏历史恢复；**不会自动修改原始存储记录**。

## 恢复与上线边界

1. 当某篇草稿提示“存储记录不完整或损坏”时，不要反复覆盖保存；在有授权的情况下先检查独立 R2 备份和已有离线导出，再决定如何修复异常记录。
2. GitHub 自动测试仅模拟损坏、保留记录和恢复冲突。Cloudflare 真实 KV/D1/R2 的兼容性需要在预览环境以合成草稿进行验证。
3. 新逻辑以现有 `savePrivateDraft` 生成的 schema 1 记录为基准。如果有历史系统写入的非规范旧记录，应先独立备份并核实兼容性，不能不经验证迁移。
4. 此改动建立在尚未合并的私人草稿分支之上，**不得单独当作生产功能已上线**。

# Firefly 后台安全基线（2026-10-20）

本文件是维护说明，不会被前台用作文章，也不会修改前台 UI。

## 已确认的边界

- `07xh/Firefly` 的主仓库为 **public**。截至本次核对，`src/content/posts/` 下有 19 个 Markdown/MDX 文章文件：其中 1 个带 `draft: true`，1 个带非空 `password`；不记录密码值。
- `draft: true` 和未来定时发布日期只控制正式网站是否生成文章页面，**无法保护公开 Git 仓库里的原始文件和历史版本**。
- 网页端加密组件用密码对输出 HTML 做加密，但文章源文件中的 `password` 和未加密正文依然可能公开。因此该功能只适合非敏感内容的阅读交互，不适合保存私人资料。
- 后台已有上述风险提示。本次 **不删除密码保护功能、不改变旧文章和前台 UI**，也不声称公开仓库中的历史内容已经保密。

## 本批安全改动

管理员会话由高熵随机 token 标识，KV 只保存 token 哈希索引。此次新增 `authTag`：使用当前 Worker 管理员密码对包含 token 的固定用途字符串计算 HMAC-SHA-256，标签仅保存在 KV 中，不暴露密码或 token。请求验证时重新计算标签：

1. 密码没变：现有登录会话可正常使用，8 小时后到期。
2. 管理员密码更改：使用旧密码创建的会话验证失败并删除，必须重新登录。
3. 首次部署新版时：旧格式会话没有 `authTag`，安全起见全部失效，需重新登录一次。
4. 密码与加密标签均不写入 GitHub 仓库。自动测试只使用虚构测试密码。

依然保留原有 Cookie 属性（`__Host-`、`HttpOnly`、`Secure`、`SameSite=Strict`）、KV 过期和后台同源检查。

## 本次不做的修改

- 不调整前台 HTML、CSS、组件或布局。
- 不修改文章原文件、文章加密行为或已有后台编辑能力。
- 不改变 Cloudflare Secrets 的名称、KV namespace 和域名配置。
- 不更改部署平台，亦不合并其他未验证 PR。

## 上线与验收

CI 使用 `node --import tsx --test scripts/admin-session.test.mjs` 检查会话建立、校验、密码变更、旧会话、过期、Cookie 和退出登录。

合并后首次访问管理后台，需要重新登录一次。建议在预览环境验证：成功登录 → 访问后台 API → 退出登录 → 访问应返回 401；更换管理员密码后，旧 Cookie 必须失效，新密码能够登录。

**注意：** 新增会话验证不能解决“公开仓库储存私人正文”的问题。真正的私密内容必须迁移到私有 Git 仓库或带服务端鉴权的私有存储，随后处理已暴露的访问密码及历史记录。此迁移应作为独立 PR 设计与验证，不能简单修改 `draft` 标记。

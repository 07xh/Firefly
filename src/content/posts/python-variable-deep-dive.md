在 Python 中，变量常被误解为“装数据的盒子”。更准确的说法是：变量是名字，它绑定到某个对象。执行 `a = 10` 时，Python 先创建或找到整数对象 `10`，再把名字 `a` 绑定到它。名字本身没有类型，对象才有类型；变量可以先后绑定到不同类型的对象。

## 一、对象、身份与类型

每个对象都有身份、类型和值。`id(obj)` 返回身份，`type(obj)` 返回类型。`is` 比较身份，`==` 比较值。两个列表值相等，但不一定是同一个对象。CPython 会缓存部分小整数和驻留部分字符串，所以某些 `is` 结果为 True 属于实现细节，不应作为比较值的依据。

## 二、赋值是重新绑定

`a = [1, 2]` 让 `a` 指向列表对象。`b = a` 没有复制列表，只是让 `b` 绑定到同一对象，因此 `b is a` 为 True。通过 `a.append(3)` 修改对象，`b` 也能看到变化。若写 `a = a + [4]`，右侧先产生新列表，再让 `a` 绑定新对象，`b` 仍指向旧列表。理解“修改对象”和“重新绑定名字”的区别，是掌握 Python 变量的关键。

## 三、可变与不可变

整数、字符串、元组等不可变对象不能被原地修改。`s += 'x'` 看起来像修改，实际可能创建新字符串并重新绑定名字。列表、字典、集合等可变对象可以原地变化。对可变对象使用 `+=` 通常调用原地方法，可能修改共享对象；使用 `+` 往往创建新对象。不要只看运算符，要判断对象是否被原地修改。

## 四、别名与复制

多个名字指向同一可变对象时，它们互为别名。若需要独立副本，可用浅拷贝，如 `b = a.copy()` 或 `b = list(a)`。浅拷贝只复制外层容器，内部可变元素仍共享；嵌套结构需要 `copy.deepcopy()`。是否复制取决于需求，而不是“赋值就会复制”。

## 五、参数传递

Python 的参数传递常被称为“对象引用传递”或“按共享传参”。函数收到的是对象的引用。函数内重新绑定参数名，不影响外部名字；但若原地修改可变参数，外部对象会变化。例如传入列表并 `append`，调用者能看到结果；若在函数内写 `items = []`，只是让局部名字指向新对象。默认参数只在定义时求值一次，因此不要用可变对象作默认值，推荐 `None` 加函数内初始化。

## 六、作用域与名字解析

名字解析遵循 LEGB：局部、外层函数、全局、内置。函数内赋值默认创建局部名字；读取外层变量可形成闭包；要修改外层函数变量用 `nonlocal`，修改模块级变量用 `global`。但滥用全局变量会让数据流难追踪。`del` 删除的是名字绑定，不是直接销毁对象；没有引用后对象才可能被回收。CPython 主要用引用计数，并配合循环垃圾回收。

## 七、类型注解不改变运行

`a: int = 1` 只是给名字加注解，不会强制类型，也不会在运行时自动检查。它服务于可读性和工具。变量仍可重新绑定为字符串。动态类型带来灵活，也要求开发者通过测试、命名和小函数控制风险。

## 八、常见误区

把变量当盒子，会误以为赋值复制了对象；把 `is` 当 `==`，会得到不稳定结果；忽视可变默认参数，会跨调用共享状态；混淆原地修改与重新绑定，会导致别名问题。建议记住三句话：名字绑定对象；对象有类型和身份；修改对象与改绑名字是两件事。

总结：Python 变量不是数据容器，而是对象的引用名字。赋值建立或改变绑定；可变对象可能被共享；函数参数传递的是对象引用；作用域决定名字可见性。抓住“名字—对象—引用”这条主线，许多看似奇怪的行为都会变得清晰。

# Python 程序书写格式完全教程：从第一行代码到规范程序

刚学 Python，很多人能看懂 `print("你好")`，但真正自己写程序时，问题就来了：

- 为什么有的语句末尾有冒号 `:`，有的没有？
- 为什么 `if` 下面要空四格？不空会怎么样？
- 程序必须一行一行写吗？太长的代码能不能换行？
- `a=3` 和 `a = 3` 都能运行，那到底应该怎样写？
- 为什么要把代码写进 `def main():`？程序究竟从哪里开始执行？
- 报错 `IndentationError`、`SyntaxError` 时，应该先检查什么？

这些问题属于**Python 程序的书写结构和组织方式**，不只是某个符号的意思。

这篇教程不假定你已经会写完整程序。每章采用**先看现象 → 解释原理 → 对照正确与错误 → 亲自运行**的方式。文章最后还会带你写出一份能直接运行的成绩分析程序。

> **先明确一个重要区别：** “程序能不能运行”和“程序写得规不规范”不是一回事。例如 `score=92` 往往能运行，但 `score = 92` 更清晰。相反，`if score >= 60:` 后面没有正确缩进，就可能直接报错。前者属于**风格建议**，后者属于**语法要求**。

## 一、先看懂：一段完整 Python 程序长什么样？

先看一段简短、规范的程序：

```python
# 1. 准备数据
name = "小明"
score = 92

# 2. 根据成绩做判断
if score >= 60:
    result = "通过"
else:
    result = "未通过"

# 3. 显示最终结果
print(f"{name}的成绩是{score}分，结果：{result}")
```

**运行结果：**

```text
小明的成绩是92分，结果：通过
```

即使你暂时不理解每个符号，也可以按顺序看出三个步骤：

1. **先准备数据**：用 `=` 给 `name`、`score` 赋值。
2. **再处理数据**：用 `if` 判断条件，为 `result` 选择一个结果。
3. **最后输出数据**：用 `print()` 把最终信息显示出来。

留意它的外观：有些行顶格、有些行缩进；不同任务之间用空行隔开；注释说明某一部分在做什么。

这些不是随便排出来的。下面逐一解释。

### 程序通常保存在哪里？

最常见的 Python 源代码文件扩展名是 `.py`，例如：

```text
hello.py
grades.py
main.py
```

在编辑器中输入代码、保存为 `hello.py`，然后让 Python 解释器运行这个文件，就能执行里面的语句。一般把代码保存为 **UTF-8 编码**，可以正常使用中文字符串与注释。

你也可以在 Python 交互式环境里一行一行输入代码，但本篇重点讲 **`.py` 文件中的程序写法**。

## 二、一行代码是什么？为什么程序通常从上往下执行？

### 1. 最基础的规则：一行放一条简单语句

```python
a = 10
b = 20
total = a + b

print(total)
```

**运行结果：**

```text
30
```

一般执行顺序是：

1. 让 `a` 指向 10。
2. 让 `b` 指向 20。
3. 计算 `a + b`，把结果 30 交给 `total`。
4. 输出 `total`。

这种写法容易阅读：**一行主要完成一件事**。但要注意，遇到 `if`、循环、函数时，程序执行顺序还会受到判断、重复和调用的影响，不能机械地认为每一行只执行一次。

### 2. 写在同一行可不可以？

可以用分号 `;` 把一些简单语句写在同一行：

```python
a = 10; b = 20
print(a + b)
```

**运行结果：**

```text
30
```

虽然能运行，但新手不建议这样写。它让断点调试、修改与排查更困难。

**推荐写法：**

```python
a = 10
b = 20

print(a + b)
```

记住：**能写在一行，不代表应该挤成一行。**

### 3. 一条语句太长，能不能分成多行？

当然可以。比如写一个列表：

```python
scores = [
    88,
    92,
    76,
    95,
]

print(scores)
```

**运行结果：**

```text
[88, 92, 76, 95]
```

为什么列表中间换了这么多行却没出错？因为 Python 看到还没闭合的方括号 `[`，知道这条表达式**还没有写完**，会继续读取后面的行，直到碰到匹配的 `]`。

圆括号 `()`、方括号 `[]`、花括号 `{}` 内部，通常也支持这种自然的跨行写法：

```python
total = (
    10
    + 20
    + 30
)

print(total)
```

**运行结果：**

```text
60
```

> **原理：** 你按 Enter 换出的是一条“物理行”；Python 分析的是一条条完整的“逻辑行”。在未闭合的括号内，多行代码可以共同组成一个表达式。初学者优先用括号换行，比较安全、清楚。

有时也能看到反斜杠 `\` 来续行，但它容易被多余空格或注释影响。写新代码时，**优先使用括号换行**。

### 4. 空行会执行吗？

```python
name = "小明"

score = 92

print(name, score)
```

中间的空行不会输出内容，也不会创建新变量；它主要是为了**把不同的思路分开**。空行不是结束代码块的方式，这一点下一章尤其重要。

## 三、全篇最重要：缩进为什么是 Python 语法的一部分？

有些语言会使用花括号包住代码块；Python 常用**冒号 + 缩进**来表达程序结构。

### 1. 什么叫“代码块”？

看下面这个例子：

```python
score = 92

if score >= 60:
    print("成绩及格")
    print("请继续努力")

print("本次判断完成")
```

**运行结果：**

```text
成绩及格
请继续努力
本次判断完成
```

这里的结构可以理解成：

| 代码位置 | 属于哪个范围 |
| --- | --- |
| `if score >= 60:` | 条件头部，顶格 |
| `    print("成绩及格")` | 缩进 4 个空格，属于 `if` |
| `    print("请继续努力")` | 同样缩进 4 个空格，也属于 `if` |
| `print("本次判断完成")` | 回到顶格，已离开 `if` |

为什么最后一行不在 `if` 里？因为它回到了顶格位置。这种**一组处于同一级缩进的语句**，就形成了一个代码块。

### 2. 把条件改成不成立，观察差别

```python
score = 50

if score >= 60:
    print("成绩及格")
    print("请继续努力")

print("本次判断完成")
```

**运行结果：**

```text
本次判断完成
```

程序先判断 `50 >= 60`，结果是 `False`，因此跳过 `if` 下面缩进的两行；最后一行不受条件限制，仍会执行。

所以，**缩进决定了哪些语句受到条件、循环、函数等结构控制**，绝不是为了把代码排得好看。

### 3. 为什么通常缩进 4 个空格？

Python 根据缩进深度辨认代码块层级；广泛使用的 [PEP 8](https://peps.python.org/pep-0008/) 编码风格推荐**每一级缩进使用 4 个空格**。

```python
score = 92

if score >= 60:
    print("第一层缩进")

    if score >= 90:
        print("第二层缩进")

print("回到最外层")
```

**运行结果：**

```text
第一层缩进
第二层缩进
回到最外层
```

注意第二个 `if` 比第一个 `if` 多缩进一级，因为它处在外层 `if` 的代码块之中。每进入一个新层级，就再向右缩进 4 个空格。

**4 个空格是推荐风格，不是说 Python 语法只能接受 4 个空格**；语法真正需要的是同一代码块内缩进一致。为了避免混乱，日常统一使用 4 个空格。

### 4. 对照：哪些缩进会报错？

下面是**错误写法示意，不要当作完整可运行的示例复制**：

```text
if 92 >= 60:
print("及格")
```

因为冒号后本应出现缩进的代码块，却直接顶格写下一条语句，所以会报 `IndentationError`。

另一种错误是同级代码没有对齐：

```text
if 92 >= 60:
    print("第一行")
  print("第二行")
```

这一行只有两个空格，既不属于上面的 4 空格层级，也没有回到外层；会出现缩进相关错误。

**更稳妥的办法：** 在编辑器里将 Tab 键设置为插入 4 个空格，不要在同一个缩进结构中混用 Tab 字符和空格。混用不一致时可能出现 `TabError`。

### 5. 缩进是怎么被 Python 理解的？

可以先理解为：

1. Python 读取源代码，识别出每行开头的缩进深度。
2. 从较浅的层级进入较深层级时，形成“开始一个新代码块”的信息。
3. 从较深的层级退回较浅层级时，形成“结束代码块”的信息。
4. 解释器再按照这些结构理解哪些语句属于 `if`、`for`、`def` 等。

在 Python 词法分析的术语里，会涉及 `INDENT`、`DEDENT` 这类标记。**你无需记住这些英文术语，只需理解：行首空格会参与程序结构的判断。**

### 6. 如果暂时还不知道代码块里写什么？

Python 不允许一个要求代码块的语句后面什么都不写。如果只是临时占位置，可以写 `pass`：

```python
score = 92

if score >= 60:
    pass  # 先留空，之后再补功能

print("程序继续运行")
```

**运行结果：**

```text
程序继续运行
```

`pass` 的作用就是**什么都不做**，但它是一条合法语句，能作为暂时的占位内容。

## 四、冒号 `:`、分支和循环：如何正确开头与结束？

### 1. 哪些语句后面常需要冒号？

| 结构 | 什么时候用 | 基础格式 |
| --- | --- | --- |
| `if` | 如果条件成立就执行 | `if 条件:` |
| `elif` | 否则再判断另一条件 | `elif 条件:` |
| `else` | 前面条件都不满足时执行 | `else:` |
| `for` | 遍历一组数据 | `for 元素 in 序列:` |
| `while` | 条件成立时反复执行 | `while 条件:` |
| `def` | 定义函数 | `def 函数名(...):` |
| `class` | 定义类，属于进阶内容 | `class 类名:` |

`if`、`for`、`while` 等结构的**头部行**在结尾使用冒号，随后写缩进代码块。不是所有 Python 语句末尾都要加冒号，`print("你好")` 和 `score = 92` 通常不需要。

### 2. `if`、`elif`、`else` 为什么要对齐？

```python
score = 82

if score >= 90:
    result = "优秀"
elif score >= 60:
    result = "合格"
else:
    result = "继续练习"

print(result)
```

**运行结果：**

```text
合格
```

Python 会按顺序检查：

1. `82 >= 90` 不成立，跳过第一个分支。
2. `82 >= 60` 成立，执行第二个分支，将 `result` 设为 `"合格"`。
3. 前面已有一个分支执行，`else` 不再执行。

`if`、`elif`、`else` 都对齐，是因为它们属于**同一组条件分支**。各自内部的动作才需要往右缩进。

### 3. `for` 的代码块为什么可能重复执行？

```python
scores = [88, 92, 76]

for score in scores:
    print(score)

print("全部打印完毕")
```

**运行结果：**

```text
88
92
76
全部打印完毕
```

`for score in scores:` 表示依次取出列表里的元素，并把当前元素交给 `score`。循环体中缩进的 `print(score)` 每取出一个元素就执行一次。

末尾的 `print("全部打印完毕")` 顶格写，因此**循环结束后才执行一次**。

### 4. `while` 为什么有时会一直运行？

```python
count = 1

while count <= 3:
    print(count)
    count += 1

print("循环结束")
```

**运行结果：**

```text
1
2
3
循环结束
```

流程是：先检查 `count <= 3`，成立就执行缩进代码；`count += 1` 每次让计数增加 1，再次回到条件判断。当 `count` 变成 4，条件不成立，退出循环。

如果忘记修改 `count`，条件可能始终成立，程序便会持续循环。**写 while 时一定思考：什么情况能让条件最终变成 False？**

### 5. 冒号不总是表示代码块

不要看到 `:` 就认定下一行必须缩进。它还可以出现在字典和切片里：

```python
student = {"name": "小明", "score": 92}
numbers = [10, 20, 30, 40]

print(student["name"])
print(numbers[1:3])
```

**运行结果：**

```text
小明
[20, 30]
```

- 在字典里，`"name": "小明"` 的冒号分隔键和值。
- 在切片里，`[1:3]` 的冒号表示索引范围。
- 只有在 `if 条件:` 等**复合语句的头部**，冒号才和后面的代码块结构相对应。

## 五、空格、换行与括号：哪些是必须，哪些是规范？

这章很重要，因为初学者经常把**语法正确性**和**书写美观**混为一谈。

### 1. 赋值和比较运算符周围通常留一个空格

下面两行对 Python 来说通常都能运行：

```python
a=3
b = 5

print(a+b)
print(a + b)
```

**运行结果：**

```text
8
8
```

但推荐第二种风格，因为读起来更容易区分变量和运算：

| 不推荐 | 推荐 | 原因 |
| --- | --- | --- |
| `a=3` | `a = 3` | 赋值关系更清晰 |
| `a+b` | `a + b` | 更容易识别运算符 |
| `if a>0:` | `if a > 0:` | 条件更易读 |
| `x=1;y=2` | 分成两行 | 一行少做几件事 |

**原理：** 大多数运算符两边的空格属于风格问题，Python 可以识别 `a=3`；但像 `if` 这样的关键字和后面的名称，需要能被正确分隔，不能随意粘连成另一个名字。

### 2. 括号里面通常不额外加空格

**推荐：**

```python
print("你好")
scores = [88, 92, 76]
student = {"name": "小明"}
```

尽量不要写得过于松散，例如 `print( "你好" )` 或 `scores = [ 88, 92 ]`。虽然有些写法合法，但不利于保持统一风格。

函数调用时，函数名和左圆括号之间通常也**不加空格**：`print("你好")`，而不是 `print ("你好")`。

### 3. 逗号后可以留空格，逗号前通常不留

```python
scores = [88, 92, 76]
print("姓名", "小明", "成绩", 92)
```

列表中相邻元素之间使用英文逗号 `,`；逗号后留一个空格能让内容更清晰。

**重点：** Python 代码里必须用它要求的英文标点。把 `,` 换成中文逗号 `，`、把 `(` 换成全角左括号 `（`，都可能出现语法错误。

### 4. 超长的一行，推荐使用括号拆开

```python
message = (
    "这是一段比较长的说明，"
    "拆成多行后仍然便于阅读。"
)

print(message)
```

**运行结果：**

```text
这是一段比较长的说明，拆成多行后仍然便于阅读。
```

在这段代码里，两个相邻的字符串字面量会被 Python 合并。只有把 `message` 直接写成一个跨行字符串，而又没有合适的引号或括号结构，才可能引起语法问题。

### 5. 一行最多能写多少字符？

Python 不是因为某一行达到固定的 79、88 或 100 字符就拒绝执行程序。

[PEP 8](https://peps.python.org/pep-0008/) 建议普通代码行尽量控制在 **79 个字符**左右（文档与团队可能采用其他约定），主要为了阅读和代码审查。实际项目可以使用统一的格式化工具与团队约定。

**不要把风格建议误当成 Python 的硬性语法规则。**

## 六、变量与文件怎么命名，代码才容易读？

### 1. 变量名先要符合语法

```python
student_name = "小明"
total_score = 92
score2 = 88
```

Python 标识符通常可以包含字母、数字和下划线，但**不能以数字开头**，也不能使用 `if`、`for`、`class` 等关键字作为变量名。

例如下面这些不是合适的变量名：

```text
2score = 90       # 不能用数字开头
student-name = 90 # 减号不是变量名的一部分
class = "A"       # class 是关键字
```

这是**语法错误示意**，不应直接放入运行程序中。

### 2. 大小写不同，就是不同的变量

```python
score = 92
Score = 60

print(score)
print(Score)
```

**运行结果：**

```text
92
60
```

`score` 和 `Score` 是两个不同的名字。遇到 `NameError`（名称未定义）时，一个常见排查方向就是检查**有没有拼错大小写**。

### 3. 为什么很多 Python 变量名带下划线？

这是一种广泛使用的约定，叫作 `snake_case`：

```python
student_name = "小明"
total_score = 92
average_score = 89.5
```

单词之间用下划线分隔，不必挤在一起。比起 `sn`、`ts` 这种过短的变量名，含义明确的命名能帮助你过几天再看代码时仍然读得懂。

| 用途 | 常见约定 | 示例 |
| --- | --- | --- |
| 普通变量 | 小写字母和下划线 | `total_score` |
| 函数名 | 小写字母和下划线 | `calculate_average` |
| 类名 | 单词首字母大写的形式 | `StudentRecord` |
| 常量（约定） | 大写字母和下划线 | `PASS_SCORE = 60` |
| Python 文件名 | 简短、小写、可带下划线 | `student_scores.py` |

注意 `PASS_SCORE` 用大写是**约定**，并不是 Python 在语法上禁止修改这个变量。

### 4. 不要随意拿内置函数名当变量

```text
list = [1, 2, 3]
print = "你好"
```

这样的赋值并非都属于语法错误，但会用自己的变量名**遮住** Python 内置的 `list`、`print`，后续再调用时容易出现混乱。

更推荐：

```python
numbers = [1, 2, 3]
message = "你好"
print(message)
```

## 七、注释、文档字符串与空行：怎样帮助别人理解代码？

### 1. `#` 注释不参与正常计算

```python
# 记录本次成绩
score = 92

# 判断是否达到及格线
is_passed = score >= 60

print(is_passed)
```

**运行结果：**

```text
True
```

注释是写给读代码的人看的。`#` 在字符串外通常表示一条注释的开始；字符串 `"#"` 里的井号只是普通字符。

### 2. 好注释讲“为什么”，而不只是复述代码

下面这样的注释信息量不大：

```python
score = 92  # 把 92 赋值给 score
```

更有用的是解释上下文：

```python
PASS_SCORE = 60  # 本练习假设 60 分是及格线

score = 92
print(score >= PASS_SCORE)
```

因为代码本身已经能看出“赋值”，注释应该补充**读代码时不容易看出的原因或约定**。

### 3. 三引号和文档字符串不是同一种“普通注释”

你会看到这种写法：

```python
def double(number):
    """返回输入数字的两倍。"""
    return number * 2

print(double(5))
```

**运行结果：**

```text
10
```

函数体开头的三引号字符串，在这种位置可以成为**文档字符串（docstring）**，用于介绍函数用途，工具也可以读取它。

**原理区别：** `#` 后面的注释不会作为普通表达式进入程序；三引号包住的内容本质上仍然是**字符串字面量**。所以不要把任意位置的三引号都当作真正的注释。

### 4. 空行如何帮助分组？

```python
# 第一组：准备数据
name = "小明"
score = 92

# 第二组：计算
passed = score >= 60

# 第三组：输出
print(name, passed)
```

在简单脚本里，不同任务之间空一行就够。按照 PEP 8 的惯例，**文件顶层的函数定义之间通常空两行**，函数内部的逻辑段落根据需要空一行。

这不是说“Python 必须空两行才允许定义下一个函数”，而是帮助读者更快识别结构。

## 八、函数怎样写，为什么值得把程序分成小块？

代码开始变长后，如果所有内容都挤在一起，就不容易修改。**函数**让我们给一段可以重复使用的功能取一个名字。

### 1. 一个函数的基本书写格式

```python
def greet(name):
    message = f"你好，{name}"
    return message

print(greet("小明"))
```

**运行结果：**

```text
你好，小明
```

逐部分拆解：

| 部分 | 含义 |
| --- | --- |
| `def` | 表示开始定义函数 |
| `greet` | 函数的名字 |
| `(name)` | 形参：调用函数时接收数据的名字 |
| `:` | 函数代码块开始 |
| 缩进的两行 | 函数内部执行的代码 |
| `return message` | 把结果返回给调用处 |

### 2. 为什么 `def` 后的代码不会立刻执行？

```python
def greet():
    print("你好")

print("开始")
greet()
print("结束")
```

**运行结果：**

```text
开始
你好
结束
```

Python 运行到 `def greet():` 时，是在**定义函数**，并不马上执行函数体中的 `print("你好")`。

直到后面遇到 `greet()`，函数才被调用。调用结束后，程序回到调用位置继续执行下一行。

这也解释了为什么 `def` 后必须有缩进：那些语句属于函数体，而不是文件顶层立即执行的语句。

### 3. `return` 和 `print()` 完全不同

这是零基础阶段特别容易混淆的问题：

```python
def add(a, b):
    return a + b

result = add(3, 5)
print(result)
```

**运行结果：**

```text
8
```

`return` 是把结果交回给调用者。因为返回了 `8`，`result` 才能保存 `8`；最后的 `print(result)` 只是把它显示出来。

反过来，如果函数只负责打印：

```python
def show_sum(a, b):
    print(a + b)

result = show_sum(3, 5)
print(result)
```

**运行结果：**

```text
8
None
```

第一行 8 是函数内部打印的；因为函数**没有明确返回一个结果**，调用得到的返回值是 `None`。

> **关键理解：** `return` 是“把值送回去”，`print()` 是“把内容显示出来”。要让其他代码继续使用计算结果，通常应该返回值。

### 4. 用函数管理重复逻辑

```python
def is_passed(score):
    return score >= 60

print(is_passed(92))
print(is_passed(55))
```

**运行结果：**

```text
True
False
```

如果以后及格规则发生变化，只需要重点修改函数中的判断逻辑，而不必在每个调用位置重复改同样的比较式。

## 九、整份程序通常如何安排？从 `import` 到 `main()`

当程序变成一个较完整的 `.py` 文件时，你会见到类似结构：

```python
# 1. 导入需要的工具
import math

# 2. 定义常量
PASS_SCORE = 60


# 3. 定义可以复用的函数
def circle_area(radius):
    return math.pi * radius ** 2


def main():
    radius = 2
    area = circle_area(radius)
    print(f"面积：{area:.2f}")


# 4. 运行脚本时执行入口
if __name__ == "__main__":
    main()
```

**运行结果：**

```text
面积：12.57
```

这段代码的组织顺序很常见：

1. **`import`**：先导入程序要使用的模块。
2. **常量**：集中写以后可能重复使用的固定配置。
3. **函数定义**：把具体任务拆成小函数，方便查找与复用。
4. **入口**：通过 `main()` 协调运行整个程序。

### 为什么最下面要写 `if __name__ == "__main__":`？

不要被双下划线吓到。可以先把 `__name__` 理解成 Python 给当前模块提供的一个特殊名称。

- 当你**直接运行这个文件**时，`__name__` 通常是 `"__main__"`，条件成立，于是调用 `main()`。
- 当别的 Python 文件**导入这个模块**时，它的 `__name__` 通常不是 `"__main__"`，因此不会因为导入就直接运行这里的 `main()`。

这么写的目的，是把“**提供功能**”与“**直接运行演示**”分开，便于后续复用。

> **初学者不用强行套模板：** 学到 `print`、`if`、列表时，可以直接写简单脚本。代码变长、开始写多个函数时，再考虑 `main()` 和运行入口的写法。`main()` 是常见组织习惯，**不是每份 Python 程序都必须有**。

## 十、综合实战：亲自写出一份清晰的成绩分析程序

这部分把前面学的格式规则串在一起。假设记录了三次成绩，希望计算平均分，并给出简单评价。

### 第一步：明确程序准备做什么

输入数据是 `[88, 92, 95]`。

程序需要完成三个小任务：

1. 计算成绩平均数。
2. 根据平均数判断评价。
3. 输出次数、平均分与评价。

我们将“计算平均数”和“获取评价”写成两个函数，再由 `main()` 把它们连接起来。

### 第二步：完整代码（可以复制运行）

```python
# 成绩分析练习：数据列表至少有一个成绩

def calculate_average(scores):
    total = 0

    for score in scores:
        total += score

    return total / len(scores)


def get_comment(average):
    if average >= 90:
        return "优秀"
    elif average >= 60:
        return "合格"
    else:
        return "继续努力"


def main():
    scores = [88, 92, 95]

    average = calculate_average(scores)
    comment = get_comment(average)

    print(f"记录次数：{len(scores)}")
    print(f"平均分：{average:.1f}")
    print(f"评价：{comment}")


if __name__ == "__main__":
    main()
```

**运行结果：**

```text
记录次数：3
平均分：91.7
评价：优秀
```

### 第三步：按执行顺序拆解

**第一阶段：读取函数定义**

Python 首先读到 `def calculate_average(scores):`、`def get_comment(average):`、`def main():`，建立这些函数定义。此时**不会直接执行函数内部的计算**。

**第二阶段：进入 `main()`**

文件直接运行时，底部判断成立，调用 `main()`。第一行建立成绩列表 `[88, 92, 95]`。

**第三阶段：计算平均数**

`calculate_average(scores)` 会接收列表，先把 `total` 设为 0，再使用 `for` 依次将三个成绩加进去。

`total` 最终是 `88 + 92 + 95 = 275`。`len(scores)` 为 3，所以平均值是 `275 / 3`，约等于 91.6667。

**第四阶段：给出评价**

`get_comment(average)` 检查平均数，`91.666... >= 90` 成立，因此返回 `"优秀"`。其他分支不执行。

**第五阶段：格式化输出**

`f"{average:.1f}"` 将平均分格式化为小数点后一位，所以显示 `91.7`。

### 第四步：这份程序为什么算比较规范？

| 书写做法 | 解决的问题 |
| --- | --- |
| 每一级缩进 4 个空格 | 清楚标出函数、循环和条件的层级 |
| `calculate_average` 这样的命名 | 一眼看出函数用途 |
| 不同函数之间留空行 | 容易辨认程序结构 |
| 用 `return` 返回计算值 | 计算结果可以交给其他函数使用 |
| `main()` 集中组织程序 | 执行流程有清楚的入口 |
| 使用 f-string 输出 | 输出文字和变量值容易对应 |

**本例的前提：** 成绩列表非空。如果传入空列表，`len(scores)` 为 0，除法会出现 `ZeroDivisionError`。真实程序应根据需求补上空列表处理，这属于下一阶段的输入校验和异常处理。

## 十一、调试时最常见的格式错误：如何定位？

代码写错不等于“自己不会编程”。初学时最好先学会根据报错定位问题。

| 错误名称 | 常见原因 | 先检查什么 |
| --- | --- | --- |
| `SyntaxError` | 冒号、括号、引号等语法不完整 | 报错行及其上一行的标点 |
| `IndentationError` | 本该缩进却没缩进，或缩进层级不合法 | 行首空格、代码块是否对齐 |
| `TabError` | Tab 与空格缩进混用不一致 | 编辑器是否统一使用空格 |
| `NameError` | 使用了未定义的名称 | 变量是否先赋值、拼写和大小写 |
| `TypeError` | 对不支持的类型进行操作 | 数值与字符串有没有混用 |
| `IndexError` | 列表索引越界 | 索引是否从 0 开始 |

### 示例 A：忘记冒号

**错误示意：**

```text
score = 92
if score >= 60
    print("通过")
```

`if` 的条件行末尾缺少 `:`，Python 无法按合法的复合语句结构理解它。

**正确写法：**

```python
score = 92

if score >= 60:
    print("通过")
```

### 示例 B：缩进不属于同一层

**错误示意：**

```text
if 92 >= 60:
    print("第一句")
  print("第二句")
```

第二条输出只缩进了 2 个空格，没有和上面的 4 空格层级对齐，也没有回到最外层。

**正确写法：**

```python
if 92 >= 60:
    print("第一句")
    print("第二句")
```

### 示例 C：以为 `=` 是相等判断

**错误示意：**

```text
if score = 60:
    print("刚好及格")
```

这里需要判断相等，不是赋值。应改成：

```python
score = 60

if score == 60:
    print("刚好及格")
```

### 示例 D：一段代码没输出，不一定是格式错

```python
score = 55

if score >= 60:
    print("通过")
```

这段代码**没有语法错误**，只是条件不成立，所以没有输出。

排错时先区分：“程序无法运行”还是“程序能运行，但逻辑导致没有输出”。

## 十三、最后收好这份 Python 书写检查表

在提交作业或发布程序之前，可以快速检查这些问题。

| 检查点 | 推荐做法 | 是强制语法吗？ |
| --- | --- | --- |
| 文件 | 保存为 `.py`，使用 UTF-8 | 常见约定，非所有运行方式都必须 |
| 每行任务 | 一行一条简单语句 | 主要是风格 |
| 赋值与运算空格 | `a = 3`、`a + b` | 主要是风格 |
| 缩进 | 统一每级 4 个空格 | 层级结构是语法；4 个空格是约定 |
| 冒号 | `if`、`for`、`while`、`def` 等头部末尾 | **是，属于语法** |
| 括号与引号 | 按规则成对闭合 | **是，属于语法** |
| 变量名 | 有意义，遵循 `snake_case` | 名称合法是语法；风格是约定 |
| 函数 | 功能清楚，按需要使用 `return` | 函数定义结构是语法；拆分程度是设计 |
| 注释 | 解释原因与背景，不重复代码 | 风格建议 |
| `main()` 入口 | 程序变大时可采用 | 非必需的组织习惯 |

### 一句话理解整篇教程

**Python 程序书写 = 正确的语法结构 + 清楚的逻辑组织 + 一致的编码风格。**

语法决定程序能否被正确理解；逻辑决定程序会做什么；风格决定它是否容易阅读、检查和维护。

学完这篇，可以接着阅读站内的 [《Python 常见符号详解：从括号到运算符》](/posts/Python2/) 复习 `()`、`[]`、`.`、`==`、`!=` 等符号，再通过 [《Python 格式字符简短总结》](/posts/python-format-characters/) 学习 f-string 的格式控制。真正掌握它们的办法，是亲自写一段程序，再试着解释每一行为什么要这样写。

页面“看起来不够整齐”，原因往往不在某一个大问题，而是布局、颜色、符号这三处零碎细节叠加起来：间距忽大忽小、颜色没有层次、图标和特殊字符在某些设备上显示成方框。下面按“布局 → 颜色 → 符号”的顺序给出可以落地的做法，最后附一份上线前的自查清单。

## 一、布局：先定间距刻度，再谈对齐

### 1. 用一套间距刻度，别随手写数字

布局乱，最常见的根源是每个人都凭感觉写 `margin: 13px`、`padding: 7px`。先定义一组有限的间距变量，之后只从这组值里挑：

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
}
```

数值少，选择就快，页面之间的节奏也自然统一。常见的做法是以 4px 或 8px 为基数往上叠，但不必严格成倍，够用即可。

### 2. 控制行宽，别让文字横跨整个屏幕

一行太长，眼睛回行时容易串行。给正文容器一个上限，并让它在宽屏上居中：

```css
.prose {
  max-width: 68ch;
  margin-inline: auto;
  padding-inline: var(--space-4);
  line-height: 1.7;
}
```

`ch` 是字符宽度单位，比写死像素更能适应字号变化。常见的经验值是英文正文一行 45～75 个字符，中文因为字更宽，一行 30～40 个字左右读起来比较舒服。

### 3. 响应式优先用流式布局，少堆断点

与其为每个屏宽写一套媒体查询，不如先让容器自己撑开：

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: var(--space-6);
}
```

标题字号也可以用 `clamp()` 平滑过渡，避免在小屏上过大、大屏上过小：

```css
h1 {
  font-size: clamp(1.5rem, 1.2rem + 1.2vw, 2.25rem);
}
```

### 4. 用留白表达层级

分组靠的不是分割线，而是间距：同一组内的元素靠得近，不同组之间拉开。如果撤掉所有边框和背景色，页面还能看出层次，说明布局是成立的。

## 二、颜色：先保证对比度，再追求好看

### 1. 用语义变量，不要在组件里写裸色值

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1f2328;
  --color-muted: #57606a;
  --color-border: #d8dee4;
  --color-primary: #0b62d6;
  --color-danger: #b3261e;
}
```

组件里只引用 `var(--color-text)` 这类语义名。这样改主题、调暗色模式时只需改一处，也不会出现“同一个灰色在三个文件里有三种写法”。

### 2. 对比度是硬指标

正文文字与背景的对比度建议至少达到 4.5:1，大号文字（大约 24px 以上，或加粗的 19px 左右）可以放宽到 3:1。这是 WCAG 无障碍指南 AA 级的要求。浏览器开发者工具里一般带有颜色对比度检查，改色前先量一下，比凭肉眼判断可靠。

浅灰字放在白底上很好看，但很容易不达标，尤其是 `#999` 这类常见的“次要文字色”。

### 3. 别只靠颜色传达信息

表单报错、状态标记如果只用红色或绿色区分，色觉障碍用户和黑白打印都会丢信息。给颜色配一个符号或文字：错误用红色加“✕ 错误”文案，成功用绿色加“✓ 已保存”。

### 4. 暗色模式单独调，不要靠反相

简单把颜色取反，蓝色会变橙、图标会失真。正确做法是给同一组语义变量换一套值：

```css
@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: #16181d;
    --color-text: #e6e8eb;
    --color-muted: #9aa4b2;
    --color-border: #2c3138;
    --color-primary: #6ea8fe;
    --color-danger: #f2b8b5;
  }
}
```

暗色模式下纯白文字会显得刺眼，通常用略微偏灰的白；主色也需要调亮，否则在深底上对比度不足。

## 三、符号显示：让每个字符都“有着落”

### 1. 写清楚字体栈，尤其是中英文混排

特殊字符显示成方框（俗称“豆腐块”），多半是当前字体里没有这个字形，而回退链又没接上。把字体栈写完整：

```css
body {
  font-family: system-ui, -apple-system, "Segoe UI", "PingFang SC",
    "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
}

code,
pre {
  font-family: ui-monospace, SFMono-Regular, Menlo, Consolas,
    "Liberation Mono", monospace;
}
```

中文字体放在西文字体之后，英文用西文字形、中文用中文字形，混排时字重和基线才不会跳。

### 2. 图标优先用 SVG，少依赖图标字体

图标字体一旦加载失败，页面上就会冒出一排方框或错字。内联 SVG 或直接使用系统 emoji 更稳，但要注意 emoji 在不同平台上的样式差异很大，如果它承担的是语义作用，务必配上文字说明。

### 3. 装饰性符号要对屏幕阅读器隐身

“✓”“→”“★”这类纯装饰字符，读屏软件会逐个念出来，干扰理解。加上 `aria-hidden`：

```html
<button type="button" class="btn">
  <svg aria-hidden="true" focusable="false" width="16" height="16"><!-- 图标路径 --></svg>
  保存
</button>
```

### 4. 数字对齐与全角半角

表格里的金额、百分比如果宽度不一，右对齐后会参差不齐。等宽数字可以解决：

```css
.price,
.metric,
.table-num {
  font-variant-numeric: tabular-nums;
}
```

另外，中文正文里建议统一使用全角标点，英文单词和数字用半角；中英文之间加不加空格属于排版风格，团队内保持一致即可。混用全角空格和不间断空格（`&nbsp;`）容易造成复制粘贴后出现莫名空隙，能不用就尽量不用。

### 5. 特殊符号的宽度不可假设

“→”“←”“•”“※”在不同字体里宽度不同，用它们做对齐或做占位并不可靠。需要精确对齐时，用 CSS 画、用 SVG，或者把符号包在固定宽度的容器里，而不是指望字符本身宽度一致。

## 四、上线前的自查清单

- [ ] 所有间距都来自同一组间距变量，没有游离的 13px、17px
- [ ] 正文容器有最大行宽，宽屏下不横跨整页
- [ ] 颜色都通过语义变量引用，没有散落的裸色值
- [ ] 正文对比度不低于 4.5:1，大号文字不低于 3:1
- [ ] 状态信息不只靠颜色区分，配有文字或符号
- [ ] 暗色模式下文字、边框、按钮都单独检查过
- [ ] 字体栈覆盖中文、英文、等宽三类场景
- [ ] 图标在禁用图片、字体加载失败时不会变成方框
- [ ] 装饰性符号已标记 `aria-hidden`
- [ ] 表格数字使用等宽数字并右对齐

这三块内容都不难，难的是保持一致性。先把变量和刻度定下来，后面每加一个组件，都从既有的刻度里取值，页面就会慢慢变得干净、清楚、耐看。

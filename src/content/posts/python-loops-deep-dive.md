# 真正理解 Python 循环：从重复执行到状态、遍历与算法思维

刚学 Python 时，我们很快就会写出：

```python
for i in range(3):
    print(i)
```

运行结果：

```text
0
1
2
```

但是，“会写”不代表“真正理解”。仔细想一想：

- 明明只写了一次 `print(i)`，为什么会执行三次？
- `i` 是谁创建的？它为什么依次变成 `0、1、2`？
- `range(3)` 为什么没有输出 `3`？
- `while` 和 `for` 都能重复执行代码，到底有什么本质区别？
- `break`、`continue`、`else` 改变的是哪一部分执行过程？
- 复杂的查找、统计、排序，为什么最终都离不开循环？

这篇文章不打算让你死记语法，而是从计算机如何一步一步执行程序出发，建立一个可以迁移到更复杂代码中的理解框架。

> **全文最重要的一句话：循环不是让同一段代码神奇地“同时执行很多遍”，而是让程序在不同的状态下，反复走过同一段指令。**

---

## 一、先理解：程序为什么需要循环？

假设要输出三次“开始学习”。

不用循环，可以这样写：

```python
print("开始学习")
print("开始学习")
print("开始学习")
```

写三次还能接受。如果要输出三千次呢？

循环解决的并不只是“少写几行代码”的问题。更重要的是：**把重复行为抽象成一条规则**。

```python
for i in range(3):
    print("开始学习")
```

我们写下了两个信息：

1. **做什么**：输出“开始学习”。
2. **做多少次**：重复三次。

程序自己按照规则组织执行过程。

### 1. 循环的基本结构

可以将大多数循环理解为四个部分：

| 部分 | 作用 | 简单示例 |
| --- | --- | --- |
| 初始状态 | 循环开始前是什么情况 | `count = 0` |
| 继续规则 | 什么情况下继续执行 | `count < 3` |
| 循环体 | 每一轮具体做什么 | `print(count)` |
| 状态变化 | 如何进入下一轮 | `count += 1` |

这里的**状态**，可以先理解为：程序此刻记住的变量和值。

例如，`count` 从 `0` 变成 `1`，再变成 `2`，这就叫状态发生了变化。

### 2. 循环的执行不是“复制代码”

用下面的简化示意图理解：

```text
开始
  |
建立初始状态
  |
判断能否继续 <-------+
  |                   |
 可以                  |
  |                   |
执行循环体             |
  |                   |
状态更新 ---------------+
  |
（不能继续时）
  |
结束循环，往下执行
```

注意：这只是理解一般循环的思维模型。`for` 和 `while` 的具体“继续规则”并不相同，下面会分别拆开。

## 二、while：只要条件成立，就继续执行

先看一个完整例子：

```python
count = 0

while count < 3:
    print(count)
    count += 1

print("循环结束")
```

运行结果：

```text
0
1
2
循环结束
```

### 1. Python 真正执行了什么？

| 时刻 | `count` | `count < 3` | 动作 |
| --- | ---: | --- | --- |
| 首次判断 | 0 | `True` | 输出 0，再加 1 |
| 第二次判断 | 1 | `True` | 输出 1，再加 1 |
| 第三次判断 | 2 | `True` | 输出 2，再加 1 |
| 第四次判断 | 3 | `False` | 不执行循环体，继续后面的代码 |

这张表说明一件很关键的事：

**`while` 的条件是在每一轮进入循环体之前重新判断的。**

所以它不是“先决定总共循环三次”。它只知道：**当前还能不能继续？**

### 2. 为什么需要 `count += 1`？

`count += 1` 相当于：

```python
count = count + 1
```

右边先取出旧值并加 `1`，然后把结果重新绑定给名字 `count`。

如果删掉更新语句：

```python
count = 0

while count < 3:
    print(count)
```

`count` 会一直保持 `0`，条件一直为真，循环就不会因为这个条件而结束。

这叫**无限循环**。学习时一旦误写，应及时停止程序并检查条件和变量变化。

> 判断一个 `while` 是否能结束，不能只看有没有判断条件，还要问：**有没有机制让它最终不再满足这个条件？**

### 3. 什么时候适合用 while？

当你知道“**什么时候结束**”，但不一定知道“**要执行几次**”时，`while` 往往很自然。

例如，模拟用户输入，直到输入 `q` 为止：

```python
while True:
    command = input("输入命令（q 退出）：")

    if command == "q":
        break

    print(f"收到：{command}")

print("程序已退出")
```

因为输入次数未知，所以这里不适合预先指定固定次数。

## 三、for：不是简单的“计数循环”，而是依次取值

初学者最常见的误解是：`for` 就是“循环指定次数”。

实际上，Python 的 `for` 更准确的含义是：

**从一个可迭代对象中，依次取出元素，将它绑定给循环变量，然后执行循环体。**

先看列表：

```python
scores = [82, 95, 76]

for score in scores:
    print(score)
```

输出：

```text
82
95
76
```

这里完全不需要自己写 `score += 1`。

原因是：`for` 负责从 `scores` 中获取下一项，而不是把上一项加一。

### 1. 循环变量究竟是谁创建的？

```python
for fruit in ["苹果", "香蕉", "橙子"]:
    print(fruit)
```

可以这样理解它的执行过程：

```text
取出 "苹果" → fruit = "苹果" → 执行 print
取出 "香蕉" → fruit = "香蕉" → 执行 print
取出 "橙子" → fruit = "橙子" → 执行 print
没有下一项 → 结束循环
```

更准确地说，每一轮都会将新取出的对象绑定给 `fruit` 这个名字。

所以，`for` 的变量不是凭空“自己加一”，它来自右侧的对象。

### 2. 字符串也能被遍历

```python
for letter in "PYTHON":
    print(letter)
```

每次取出一个字符。

这也解释了为什么 `for` 不只是数学计数工具：**它可以遍历数字序列、字符串、列表、字典等不同的数据。**

### 3. for 与 while 的核心区别

| 角度 | `for` | `while` |
| --- | --- | --- |
| 核心规则 | 依次取得下一个元素 | 每轮重新判断条件 |
| 常见场景 | 遍历列表、字符串、固定范围 | 等待条件变化、未知次数 |
| 谁推进过程 | 迭代器提供下一项 | 代码及外部状态推动条件变化 |
| 主要风险 | 遍历中误改容器、变量混淆 | 条件不变，造成无法结束的循环 |

它们不是“一个高级、一个低级”，而是表达不同意图的工具。

## 四、range 为什么经常让人困惑？

`range` 是初学循环时最值得真正理解的工具之一。

```python
for i in range(3):
    print(i)
```

为什么输出 `0、1、2`，而不包含 `3`？

因为 `range(3)` 表示从 `0` 开始，**到 `3` 之前停止**。

### 1. 三种常用写法

| 写法 | 产生的数值 |
| --- | --- |
| `range(4)` | `0, 1, 2, 3` |
| `range(2, 6)` | `2, 3, 4, 5` |
| `range(1, 8, 2)` | `1, 3, 5, 7` |

通用形式：

```python
range(start, stop, step)
```

- `start`：起点，包含。
- `stop`：终点，不包含。
- `step`：步长；省略时为 `1`，且不能为 `0`。

例如倒序：

```python
for n in range(5, 0, -1):
    print(n)
```

输出 `5、4、3、2、1`。

### 2. 为什么 Python 采用“不包含终点”？

一个实用理由是：区间的长度容易计算。

`range(2, 6)` 在步长为 `1` 时有 `6 - 2 = 4` 个数。

另一个理由是可以自然对应列表下标。一个有 `5` 个元素的列表，下标正好从 `0` 到 `4`。

```python
names = ["甲", "乙", "丙"]

for i in range(len(names)):
    print(i, names[i])
```

不过，如果只需要元素本身，直接写 `for name in names` 会更清楚；需要**元素和位置**时，下面的 `enumerate` 通常比 `range(len(...))` 更合适。

### 3. range 是不是提前生成了整个列表？

不是。在 Python 3 中，`range` 是一种紧凑的范围对象，支持按需提供数值，并不是先创建一个装满整数的列表。

```python
numbers = range(1_000_000)

print(type(numbers))
```

输出：

```text
<class 'range'>
```

这也体现了一个更普遍的思想：**描述一个序列的规则，并不等于立刻把所有元素都存到内存中。**

## 五、break 与 continue：改变的到底是哪一步？

它们很容易混淆，但实际控制的方向不同。

### 1. break：立即结束当前最内层循环

```python
for n in [3, 5, 7, 9]:
    if n == 7:
        print("找到了 7")
        break

    print(f"检查过：{n}")
```

输出：

```text
检查过：3
检查过：5
找到了 7
```

遇到 `break` 后，程序直接离开当前这层循环。

### 2. continue：跳过本轮剩余语句

```python
for n in range(1, 6):
    if n == 3:
        continue

    print(n)
```

输出：

```text
1
2
4
5
```

`continue` **并没有结束整个循环**，只是跳过了本轮后续代码，进入下一轮的取值或条件判断。

### 3. while 中的 continue 有一个特别重要的陷阱

看下面这个正确示例：

```python
n = 0

while n < 5:
    n += 1

    if n == 3:
        continue

    print(n)
```

输出同样是 `1、2、4、5`。

注意，`n += 1` 必须在 `continue` 之前完成。

如果把状态更新放到 `continue` 后面，某些情况下会一直跳过更新，导致循环无法按预期结束。

> **记忆方法：** `break` 是“结束这一层循环”；`continue` 是“结束这一轮剩下的工作”。

## 六、for 后面为什么还能写 else？

很多初学者看到下面的代码都会困惑：

```python
target = 7

for n in [3, 5, 7, 9]:
    if n == target:
        print("找到了")
        break
else:
    print("没找到")
```

结果是：

```text
找到了
```

`else` 并不是“如果 `if` 不成立就执行”的意思。

**循环的 `else` 在循环正常结束、没有被 `break` 中断时执行。**

如果改为查找 `8`：

```python
target = 8

for n in [3, 5, 7, 9]:
    if n == target:
        print("找到了")
        break
else:
    print("没找到")
```

就会输出：

```text
没找到
```

这是一种很适合“遍历查找”的写法，不需要额外创建 `found = False` 这样的标记变量。

两个细节也要知道：

- `while ... else` 同样存在，规则也是“没有被 `break` 中断而正常结束”。
- 即使 `for` 遍历的是空列表，正常结束时也会执行 `else`；而循环体一轮都不会运行。

不要把循环 `else` 和普通 `if ... else` 混成同一个概念。

## 七、循环如何把零散数据变成有意义的结果？

这是循环真正开始发挥价值的地方。

假设有一组学习时长记录，单位是分钟：

```python
minutes = [25, 40, 0, 35, 50]
```

我们想得到三个结果：

1. 总学习时长；
2. 平均每天学习时长；
3. 时长至少 30 分钟的日期编号。

### 1. 先用循环累加

```python
total = 0

for value in minutes:
    total += value

print(total)
```

输出：

```text
150
```

思考：为什么 `total` 必须在循环之前设置为 `0`？

因为每一轮要在**上一轮的结果**上继续增加：

```text
开始：total = 0
第1轮：total = 0 + 25  = 25
第2轮：total = 25 + 40 = 65
第3轮：total = 65 + 0  = 65
第4轮：total = 65 + 35 = 100
第5轮：total = 100 + 50 = 150
```

这个变量称为**累加器**。它承载了从之前轮次积累起来的信息。

### 2. 再用 enumerate 同时拿到位置和值

```python
minutes = [25, 40, 0, 35, 50]
total = 0
qualified_days = []

for day, value in enumerate(minutes, start=1):
    total += value

    if value >= 30:
        qualified_days.append(day)

average = total / len(minutes) if minutes else 0

print(f"总学习时长：{total} 分钟")
print(f"平均每天：{average:.1f} 分钟")
print(f"达标日期：{qualified_days}")
```

输出：

```text
总学习时长：150 分钟
平均每天：30.0 分钟
达标日期：[2, 4, 5]
```

这里同时出现了三种常见算法动作：

- **聚合**：`total += value`，不断累积结果。
- **筛选**：`if value >= 30`，只保留满足条件的项目。
- **定位**：`enumerate(..., start=1)`，记录项目处于第几天。

其中 `if minutes else 0` 是一个条件表达式，用来避免列表为空时发生除零错误。

### 3. 为什么这个例子比“打印十遍 hello”更重要？

因为它体现出循环最核心的能力：

**逐个读取数据 → 判断和处理 → 更新结果 → 最终形成信息。**

未来学习文件处理、数据分析、自动化脚本，反复出现的都会是这个模式。

## 八、怎样证明自己的循环没有算错？

我们通常会通过打印结果来测试程序。但还可以学一个更强的思考方法：**循环不变量**。

名字听起来很抽象，意思其实很朴素：

> 每一轮结束后，始终成立的一条规则。

继续看累加：

```python
numbers = [4, 6, 2]
total = 0

for value in numbers:
    total += value
```

它有一条不变量：

**已经处理过多少个数，`total` 就等于这些数的和。**

- 循环前：处理了 `0` 个数，和为 `0`，成立。
- 第一轮后：处理了 `4`，`total = 4`，成立。
- 第二轮后：处理了 `4、6`，`total = 10`，成立。
- 第三轮后：处理了 `4、6、2`，`total = 12`，成立。

当整个序列处理完，不变量就告诉我们：`total` 是全部元素之和。

这就是一种非常简化的算法正确性证明：

**初始时成立 → 每轮能保持成立 → 结束时得到目标结论。**

以后遇到“计算最大值”“查找目标”“排序”等问题，你也可以问自己：**循环运行到第 k 步时，我已经能保证什么？**

## 九、双重循环：为什么有时会变慢？

看一个打印坐标的小程序：

```python
for row in range(2):
    for col in range(3):
        print(row, col)
```

输出：

```text
0 0
0 1
0 2
1 0
1 1
1 2
```

外层 `row = 0` 时，内层跑完三轮；外层 `row = 1` 时，内层又从头跑三轮。

总执行次数为 `2 × 3 = 6`。

### 1. 什么是时间复杂度？

如果只有一个遍历 `n` 个元素的简单循环，工作量通常随 `n` 线性增长，常写为 `O(n)`。

如果两层循环都分别运行 `n` 次，内部操作是常数时间，那么总工作量通常是 `n × n`，写为 `O(n²)`。

但**不是看到两层循环，就一定是 `O(n²)`**。

例如：

```python
for row in range(rows):
    for col in range(cols):
        print(row, col)
```

总共执行 `rows × cols` 次，对应 `O(rows × cols)`。只有两个规模都用同一个 `n` 表示时，才可以简写为 `O(n²)`。

还有一种情况：某些内层循环的总执行次数受全局约束，也不能只凭缩进层数判断复杂度。

### 2. 对初学者最有用的判断法

先别急着背很多大 O 公式。直接问：

**如果输入数量翻倍，循环体总共会执行多少次？**

你对“执行次数”的理解，最终会转化成对“程序效率”的理解。

## 十、深入一层：for 背后究竟发生了什么？

前面说过，`for` 依次从一个对象中取值。

Python 为这件事定义了统一的**迭代协议**。

先用一个具体例子：

```python
numbers = [10, 20, 30]
iterator = iter(numbers)

print(next(iterator))
print(next(iterator))
print(next(iterator))
```

输出：

```text
10
20
30
```

可以把它理解为：

- `iter(numbers)`：向对象请求一个迭代器。
- `next(iterator)`：向迭代器请求下一个值。
- 没有下一项时：迭代器会通过 `StopIteration` 通知结束。

我们平常写的：

```python
for value in numbers:
    print(value)
```

就借助了这套机制。为了理解，可把它近似想象成：

```python
iterator = iter(numbers)

while True:
    try:
        value = next(iterator)
    except StopIteration:
        break

    print(value)
```

**注意：这只是展示常规取值过程的教学模型，并不等同于 Python 对所有循环情况的完整实现。** `for` 还有 `break`、`continue`、`else`、异常传播等控制规则。

这个知识有什么意义？

它解释了为什么列表、字符串、字典、`range`，甚至逐行读取文件，都能使用类似的 `for` 语法。

因为它们不必拥有相同的数据结构，只需要支持统一的迭代方式。

## 十一、六个高频误区：知道原因才能真正避坑

### 误区 1：以为 range 包含终点

```python
for i in range(1, 4):
    print(i)
```

输出 `1、2、3`，没有 `4`。终点始终不包含在生成的范围内。

### 误区 2：以为循环变量每次都自动加一

```python
for color in ["红", "绿", "蓝"]:
    print(color)
```

`color` 来自列表的每个元素。只有遍历 `range` 等数字序列时，你才会看到数值按特定步长变化。

### 误区 3：把累计变量放错位置

错误的思路：

```python
for value in [2, 3, 5]:
    total = 0
    total += value

print(total)
```

结果是 `5`，不是 `10`。

为什么？因为每一轮都重新执行 `total = 0`，之前的结果被覆盖。

正确方法是先在循环外初始化：

```python
total = 0

for value in [2, 3, 5]:
    total += value

print(total)  # 10
```

### 误区 4：以为 continue 就是 break

`break` 离开循环；`continue` 只跳过本轮剩余语句。把两者混用，会让最终统计结果产生偏差。

### 误区 5：一边遍历列表，一边删除其中的元素

```python
numbers = [2, 2, 3]

for n in numbers:
    if n == 2:
        numbers.remove(n)

print(numbers)
```

结果是：

```text
[2, 3]
```

不是预期中的 `[3]`。

原因是删除元素会改变列表的位置，而迭代过程仍在推进，导致某些元素被跳过。

更安全、也更清晰的写法是构造新列表：

```python
numbers = [2, 2, 3]
numbers = [n for n in numbers if n != 2]

print(numbers)  # [3]
```

这里的 `[n for n in numbers if n != 2]` 叫**列表推导式**。它仍然基于循环与条件筛选，只是表达更紧凑。

### 误区 6：以为循环结束后，循环变量一定不存在

```python
for n in [10, 20]:
    pass

print(n)  # 20
```

在普通模块级代码中，`for` 不会创建新的局部作用域，所以循环变量 `n` 在循环后仍可读取。

但如果循环一次都没有执行，而且 `n` 之前也没定义，那么直接读取 `n` 会产生 `NameError`。

**不要把循环后的变量值当成设计程序的主要依据。** 需要保留结果时，最好使用语义明确的变量，例如 `last_value`、`total` 或 `found`。

## 十三、最后，把循环整理成一个思维框架

学习循环真正值得记住的，不是某几段固定模板，而是下面这五个问题：

| 问题 | 实际含义 |
| --- | --- |
| **我从哪里开始？** | 初始状态是什么？ |
| **我为什么还能继续？** | 条件仍然满足，还是还有下一项？ |
| **这一轮做什么？** | 输出、计算、判断、筛选或记录？ |
| **这一轮改变了什么？** | 状态如何更新，结果如何积累？ |
| **我什么时候结束？** | 条件失效、元素耗尽，还是遇到 `break`？ |

由此可以形成一个完整的认识：

**`while` 强调“条件”**：在条件允许时重复执行。

**`for` 强调“遍历”**：按迭代协议依次取得数据。

**循环体强调“变化”**：每一轮读取当前状态，并且可能产生新的状态。

**算法强调“正确性和效率”**：不仅要得到结果，还要知道为什么得到正确结果、需要多少次操作。

当你能不运行程序，就在纸上写出每一轮变量的值；当你能解释为什么会结束、为什么不会漏掉数据；当你能从一个简单的累加例子看出更一般的算法规律——你就不只是掌握了 `for` 和 `while` 的语法，而是开始理解**计算机如何用有限的指令处理不断变化的数据**。

这才是循环结构最值得学习的部分。
